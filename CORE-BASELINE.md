# Core dependency provenance

The standalone DSH adapter consumes the host-neutral Python distribution `thaliris==0.4.2` from the Thaliris Core repository at commit [`da663e86ffea1fc8d09ea9bbec3ec8da21eeef34`](https://github.com/Iris0fTheValley/Thaliris/tree/da663e86ffea1fc8d09ea9bbec3ec8da21eeef34). The DSH native API baseline is source revision [`639ed015397290b3745d163aafe02ffee4aa3f84`](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84). The adapter keeps the authority and task ledger in Core; this repository ships no Core or Codex adapter source.

For the extracted-repository validation, a fresh `thaliris-0.4.2-py3-none-any.whl` was built from the pinned Core commit, inspected, and installed into a task-owned Python 3.11 environment. Its payload contains only the `thaliris` package (`__init__`, `authority`, `cli`, `core`, `markdown`, and `models`) plus distribution metadata; it contains no Codex-specific modules. The installed package directory was used for the packed activation smoke. Bridge and native composition checks used the matching upstream `src` tree. The tested wheel SHA-256 was `6510f864905919f09da414e169dda899427856812300e24a4f14a8dd9f1c05e1`.

The original source repository's live Web integration was verified separately against Core source revision `256f760`, including a real active task, a fifth child, denial of native root tools to that child, and an explicit `DONE` close. That observation is separate from the extracted-repository native and packed-install checks; a Desktop binary was not launched.
