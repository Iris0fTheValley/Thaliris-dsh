# Core dependency provenance

The standalone DSH adapter consumes the host-neutral Python distribution `thaliris==0.4.4` from the Thaliris Core source pin [`56e48ac299dd2c5c4b16c992db732a55b7790893`](https://github.com/Iris0fTheValley/Thaliris/tree/56e48ac299dd2c5c4b16c992db732a55b7790893). This source pin adds explicit Task-ID selection and task-scoped state and AuthorityStore paths while preserving existing `task_*` call signatures. Every new Task ID has an independent ledger under `.context/tasks/<UUID>/state.json`; a legacy singleton is retained as its own record and is never reused for a new task. DSH selects a task explicitly for each bridge operation; selection is process-local navigation and does not grant authority. The packed activation smoke built a local wheel from this source pin, installed it in an isolated Python 3.11 environment, and verified the packed runtime start/inspect/close path. No PyPI wheel or publication is claimed. The DSH native API baseline is source revision [`639ed015397290b3745d163aafe02ffee4aa3f84`](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84). The adapter keeps the authority and task ledger in Core; this repository ships no Core or Codex adapter source.

Historical extracted-repository validation used a `thaliris-0.4.3-py3-none-any.whl` built from Core commit `7f4d9acf2e642e7b3c987d4ee45ebc6589d7cc15`. Its payload contained only the `thaliris` package and distribution metadata; its SHA-256 was `c916e219c99bc52021c8d91d71ec93a5c1a1950eaa4ed71dec90be73658dec16`. This wheel predates the current Task-ID API and is not evidence for the pinned source above.

The bridge suite passes 18 tests against the pinned Core source, including independent tasks beside corrupt legacy authority, an actual Windows Junction at the legacy anchor, and rejection of a redirected task-scoped anchor. The DSH native composition, shared-client, and prompt-contract checks also passed; the packed activation smoke used local DSH archives and the isolated Core wheel described above. Earlier bridge and wheel results used Core commit 7f4d9acf2e642e7b3c987d4ee45ebc6589d7cc15 and predate Task-ID integration.

The original source repository's live Web integration was verified separately against Core source revision `256f760`, including a real active task, a fifth child, denial of native root tools to that child, and an explicit `DONE` close. That observation is separate from the extracted-repository native and packed-install checks; a Desktop binary was not launched.
