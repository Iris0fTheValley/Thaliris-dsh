# Runtime capability observations

Baseline: upstream DSH `22ddee3792402c3e70ec5f86a63c3e3e895a2f60`.

| Surface | Verified behavior | Limit |
|---|---|---|
| Core | Native subprocess imports neutral core/authority only; external anchor owns intent | Shared OS governance, not actor authentication |
| Root continuation | Native Workspace + persisted root Session/new Agent resumes exact anchor | Missing/changed native workspace anchor fails closed |
| Policy | Native Settings live forms, stored edits, revision conflicts; editable prompt and legal empty role list | Deployment paths use native ordinary plugin configuration |
| Models | Native exact route metadata and configured allowed-set membership | No route ranking or online catalog smoke |
| Children | Fresh native spawn, bounded handoff, allowlist plus body checks, immediate ID/correlation recording | Current supported provider is local in-process spawn |
| Roles | Six editable seeds (Investigator, Implementer, Focused Implementer, Reviewer, Curator, Reasoning Specialist); dispatch snapshots the selected role, recorded as `role_sha256` | Roles are adjusted by user Settings edits; no Controller role registration. Non-writing roles rely on tool grants, not a native readonly classification |
| Model per dispatch | Controller-chosen route and reasoning effort within the role's allowed routes (isolation and division of labor first, then the cheapest allowed route and lowest effort that fit the working set; no cheap route in policy is respected), checked against native model reasoning efforts and recorded with the reservation | Actual model execution is what DSH ran; not separately observed by the adapter |
| Evidence continuity | Controller register/judge/status; dispatch-registered handoff; child `thaliris_observe` bound to the exact bound child and handoff; the compact open-evidence summary (totals plus bounded items, paged) returned with the child result and with register/judge/context results | No automatic relevance or acceptance; observation without an association is returned in FINAL |
| Controller overhead (Core 0.5.1) | `thaliris_task_status` is compact by default (`view: "full"`, `since_revision` optional); `thaliris_task_judge` takes one `judgment` or an atomic ordered `judgments` batch (one revision); write results carry the new revision and the evidence summary; the dynamic-context summary is not echoed in tool results; revision conflicts keep the text `TASK_ID_OR_REVISION_CONFLICT` and add Core's `code`, `recovery` and `details.changes_since` (task-id and revision mismatch distinguished); other Core `code`/`details` errors surface the same way | Strict CAS is unchanged: nothing is rebased or merged, and `changes_since` is a bounded non-exact review hint. Native tool execution of the new fields is not covered by the local checks |
| Project identity | Core 0.5.0 `.project-identity/` read (status, get, trace) and Controller-only amend, challenge and relate (plus, Core 0.5.2, Controller-only `thaliris_task_identity_note` and `thaliris_task_identity_suggest` with no ACTIVE task needed, a session scope keyed by the native Controller id, and an `identity_offer` line on a successful close only when Core returns one) through the bridge under the authority check and task-revision CAS; actor from the native Controller identity; one summary line in the dynamic task context only when an identity exists | No path-level child write guard exists in this adapter: a child's change to `.project-identity/` is detected afterwards (Core `UNRECORDED_CHANGE` or `INVALID`, Git diff), not prevented. Relations are registered ones only; Core records a human decision the Controller asserts and cannot authenticate a human. Native tool execution of the identity tools is not covered by the local checks |
| Task context | Controller records/milestone via Core `task_update`; bounded summary as native dynamic context, re-projected after compaction and restored after restart from this root's anchored ACTIVE tasks; the first prompt assembly after a restart awaits restoration | A failed or timed-out restoration leaves the context empty; history, not fresh verification |
| Dispatch history | Each finished dispatch is one append-only `dsh-dispatch` Core record (producer `dsh:adapter`); Active Work/Pending Results keep only current routing state; legacy history in Pending Results migrates on the next adapter write; tested beyond 50 dispatches | Core's 512-record/512 KiB task bounds still apply: past them a release or close succeeds but returns the archive text as `unrecorded` |
| Execution mode | Core `switch_mode` with human instruction, authority-digest and revision CAS; refused with active work | Instruction text is Controller-asserted, not human authentication |
| Recovery | Native catalog correlation + durable terminal Session reason; reservation archived as a `dsh-dispatch` record; completed/aborted tested | Unbound/cross-process liveness remains UNKNOWN; no uncertainty auto-release |
| Memory | Optional independent capability/provider packages; async external injection, bounded read/search/write and user grants | No embeddings/vector/RAG/credential management |
| Memory writes | Disabled default, manual/review Core proposals (pending until approved), human Remote approval recorded as a `dsh-memory-approval` record, explicitly opted-in auto | Approval is human-client governance within native Host trust |
| Uninstall | Native effects dispose provider/capability; routing and close continue | Native package-manager UI installation/removal smoke is pending |
| Remote | Native Gateway SRC dispatch of templates, diagnostics, and approval; temporary Web preview rendered the client and injected its API namespace | Extracted-package verification does not launch a browser; the original source repository's live Web integration was separately verified against Core source revision `256f760` |

Tests use real native source components and a scripted LLM. They do not establish Codex managed enforcement, universal process authentication, or semantic task completion authority.
